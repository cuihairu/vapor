[:material-arrow-right: 生产部署](production.md)</div>## 为什么是 Vapor？Vapor 复用了 ASF 已验证的概念——bot 会话、动作、挂机——但重塑了交付形态：不是每台机器一个进程，而是拆成**集中控制平面**（公开 API、SQLite 支撑的编排）与**无头区域 Agent**（WebSocket 连接的执行器）。这使它适合集群式、多区域运营——ASF 的单机模型在这样的规模下不再适用。Steam 协议层本身基于 [SteamKit2](https://github.com/SteamRE/SteamKit) 构建。详细对比见[功能矩阵](feature-matrix.md)。## 快速开始=== "Docker Compose"    ```bash    git clone https://github.com/cuihairu/vapor.git    cd vapor    docker compose up -d                  # 控制平面 + Agent    docker compose --profile observability up -d   # + Prometheus 与 Grafana    ```    完整拓扑与变量见 [Docker 与 Compose](docker.md)。=== "本地 .NET"    ```bash    dotnet build Vapor.sln    export VAPOR_ENCRYPTION_KEY=0123456789abcdef0123456789abcdef    dotnet run --project src/Vapor.ControlPlane    # 控制平面    # 另开终端——Agent 需要配置身份：    export AGENT_ID=agent-1 AGENT_REGION=local    export AGENT_CONTROLPLANE_WS_URL=ws://127.0.0.1:8080/v1/agent/ws    export AGENT_API_KEY=dev-agent    dotnet run --project src/Vapor.Agent           # Agent    ```    完整变量参考见[本地运行](running.md)。## 文档| 板块 | 内容 ||---------|----------|| **入门** | [上手指南](getting-started.md) · [本地运行](running.md) · [Docker 与
